Documentation

Learn how to install EnvSave, keep your secrets in an encrypted local vault, and give AI agents opaque keys instead of real credentials.

EnvSave is open source. The code is on GitHub, and the package is @envsave/cli on npm and envsave on PyPI.

What is EnvSave?

EnvSave is a local encrypted vault for API keys, tokens, passwords and database URLs. It replaces .env files. Each secret is stored under an opaque key, such as es_7a3f2b1e9c8d4f6b. Your code uses that key to read the value at runtime.

An AI agent can read your code, your terminal history and your project files, and it still learns nothing useful. It sees only es_... keys. Those keys can't be reversed or listed, and they don't work outside your vault.

Why opaque keys?

If an LLM can read a real secret, anyone who can see the LLM's context can read it too.

  • Exfiltration: an agent with shell or HTTP access can send keys to an outside server or commit them to a public repo.
  • Prompt injection: a malicious web page or PR description can tell the agent to print .env or your environment variables.
  • Context leakage: once a key is in a transcript, it can be logged, cached or stored by third parties.
  • Painful rotation: rotating a leaked production key means downtime, redeploys and finding every place it was pasted.
app.ts
// ❌ The LLM sees the real key in your code
const openai = new OpenAI({ apiKey: "sk-proj-abc123..." });

// ❌ .env still holds the plaintext key, and agents read .env
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

// ✅ The agent only ever sees "es_7a3f...", which is useless outside your vault
import { get } from "@envsave/cli";
const openai = new OpenAI({ apiKey: get("es_7a3f2b1e9c8d4f6b") });

Pricing

Local use is free and unlimited: any number of secrets on any number of machines, with no license. You only need a license to back up or sync your encrypted vault through the EnvSave cloud. You can get a token from your dashboard.

Getting started

1. Install the CLI

terminal
npm install -g @envsave/cli

For Python projects, install the bridge too. It reads the same vault:

terminal
pip install envsave

2. Create your vault

terminal
# Creates ~/.envsave/vault.enc and asks you for a master password
envsave init

# Or import an existing .env file in the same step
envsave init --env .env

# Optional: require an SSH key as a second factor
envsave init --ssh-key ~/.ssh/id_ed25519

3. Install the agent skill

The skill tells Claude Code to use opaque keys whenever it works with secrets:

terminal
npx skills add jcsancho/envsave

4. Store a secret

terminal
$ envsave set OPENAI_API_KEY
Value for OPENAI_API_KEY: ********
Added: OPENAI_API_KEY → es_7a3f2b1e9c8d4f6b

Leave the value out and EnvSave asks for it with hidden input. This keeps it out of your shell history and protects characters like !, $ and backticks. If you run envsave set again on an existing name, the value is replaced and the opaque key stays the same, so you don't need to change any code.

5. Use it in your code

Replace process.env.OPENAI_API_KEY with get("es_7a3f2b1e9c8d4f6b"). See Using secrets in code below.

Using secrets in code

Node.js / Bun

terminal
npm install @envsave/cli
app.ts
import { get, has } from "@envsave/cli";

const apiKey = get("es_7a3f2b1e9c8d4f6b");

if (has("es_7a3f2b1e9c8d4f6b")) {
  // secret exists
}

Python

app.py
from envsave import get

api_key = get("es_7a3f2b1e9c8d4f6b")

Reads are served from an unlocked session cache, so you enter the master password once per session instead of once per read.

AI agent skill

The EnvSave skill teaches your coding agent to never hardcode or print secrets. It always writes get("es_...") calls instead. Invoke it with /envsave to migrate an existing project. The agent finds every process.env, os.getenv, dotenv import and hardcoded key, then gives you a single envsave reveal command to look up their opaque keys.

Install with skills.sh

terminal
# Interactive: pick the agent and scope
npx skills add jcsancho/envsave

# Non-interactive: global install for Claude Code
npx skills add jcsancho/envsave -g -y --agent claude-code

Install with the CLI

terminal
envsave install-skill            # asks: this project or all projects
envsave install-skill --local    # → ./.claude/skills/envsave/SKILL.md
envsave install-skill --global   # → ~/.claude/skills/envsave/SKILL.md

Claude Code is supported today. Codex and other agent platforms are planned.

Deploying to Vercel

envsave vercel pushes only the secrets you name to a linked Vercel project. You don't need a .env file on disk, and you don't need the vault in production.

terminal
# In a directory linked with `vercel link`
envsave vercel OPENAI_API_KEY DATABASE_URL

# Restrict environments (default: production, preview, development)
envsave vercel OPENAI_API_KEY --env production,preview

Each secret is uploaded twice: under its opaque key and under its clean name. Code that calls get("es_...") still works, and so does code that reads process.env.OPENAI_API_KEY.

Cloud backup & sync

With a license, you can back up your vault to the EnvSave cloud and sync it across machines. The server stores only the encrypted bytes and never sees plaintext secrets.

terminal
envsave activate <token>   # once per machine, token from your dashboard
envsave backup             # upload the encrypted vault
envsave restore            # download it (asks before overwriting)
envsave sync               # figure out the direction automatically
SituationWhat envsave sync does
Same checksumReports "Already in sync"
Local vault onlyPushes to the cloud
Cloud backup onlyPulls from the cloud
Both exist but differAsks: pull, push or cancel
Neither existsTells you to run envsave init

Setting up a new machine

terminal
npm install -g @envsave/cli
envsave activate <token>
envsave sync
envsave list

License tokens renew automatically. When a token expires and your subscription is still active, the CLI gets a new one and finishes the command you ran.

Security model

  • The vault is encrypted with AES-256-GCM. The key is derived from your master password with PBKDF2.
  • Opaque keys are HMAC-SHA256 hashes, so they reveal nothing about a secret's name or value.
  • An optional SSH key adds a "something you have" factor.
  • envsave get is rate-limited to slow down automated scraping from a compromised session.
  • Agents can read a value only when they already know its opaque key. They can't list or discover other secrets.
  • Cloud backups are end-to-end encrypted. The server stores ciphertext only.

If you forget your master password, EnvSave can't recover it. A cloud backup is encrypted with the same password, so keep the password in a password manager.

FAQ

Can an agent just run envsave export or envsave list?

Not without your master password. Commands that list names or print values by name always ask for it. A session only lets code read values by an opaque key it already knows.

Do I need to change code when I rotate a key?

No. Run envsave set KEY again. The opaque key comes from the name, so it stays the same.

How do I find the opaque key for a secret I already stored?

Run envsave reveal NAME. You can pass several names or keywords at once and enter the password once.

npm install -g @envsave/cli fails with EEXIST.

You still have the old unscoped package installed. Run npm uninstall -g envsave, then install @envsave/cli again.

Is it free?

Yes. Local use is free and unlimited. You only need a license for cloud backup and sync.

How do I report a security issue?

Please open a private security advisory on GitHub instead of a public issue.
